# Exercise demo GIFs — design

**Date:** 2026-06-17
**Branch:** `feat/library-programs`
**Status:** approved direction ("давай сделаем"); spec of record

## Goal

Attach animated demo GIFs to exercises, sourced from ExerciseDB OSS, self-hosted. Show them across surfaces:

- **List** (`/exercises`) — animated mini-GIF beside each name.
- **Exercise detail** (`/exercises/[id]`) — GIF hero under the title.
- **During an exercise** — the GIF as a dimmed background behind the timer (rest timer between sets + circuit work/rest countdown).
- **Picker / builder / template rows** — small thumbnail.

## Locked decisions

1. **Source:** ExerciseDB OSS GIFs (`oss.exercisedb.dev`). Downloaded once and **self-hosted** — the live API is "exploration only, not for production" (rate limits). No runtime calls.
2. **License:** ⚠️ ExerciseDB code is AGPL-3.0; GIF/data redistribution rights are **unspecified**. This SaaS is for sale → **resolve GIF redistribution rights before commercial launch.** Acceptable for now (owner is also first user). Tracked as an open risk.
3. **No DB migration.** Demos live as static assets + a TS manifest keyed by exercise **slug**.
4. **Key by `slug`, never by `id`.** `exercises.id` is a per-seed UUID — different in dev vs prod. `slug` (e.g. `bench-press-barbell`) is stable across environments.
5. **Coverage:** the 86 system exercises. Custom (user) exercises have no demo in v1.
6. **Surfaces:** list, detail, active strength card, rest timer, circuit timer, picker. (Owner: "везде включая список".)

## Architecture (no migration, offline-friendly)

### 1. Data acquisition — `scripts/fetch-exercise-demos.mjs` (one-time, local)

- Read the 86 seed records (`db/seed/exercises.seed.ts`) — `{ slug, nameEn }`.
- Match each to an ExerciseDB OSS exercise by normalized `nameEn`, with a hand-maintained **override map** (`{ slug: exerciseDbId | exerciseDbName }`) for mismatches.
- For each match: download the GIF → `public/exercises-demos/<slug>.gif`; generate a **static poster** (first frame) → `public/exercises-demos/<slug>.webp` (via `sharp`).
- Emit / update `lib/domain/exercises/demos.ts` (the manifest) and **log unmatched slugs** for manual override.
- Hitting the API here is fine — it is a one-time download, not a runtime dependency.
- Re-runnable + idempotent (skip already-downloaded unless `--force`).

### 2. Manifest — `lib/domain/exercises/demos.ts` (pure domain, R-7)

```ts
export type ExerciseDemo = { gif: string; poster: string }; // public paths
export const EXERCISE_DEMOS: Record<string /* slug */, ExerciseDemo>;
export function getExerciseDemo(slug: string | null | undefined): ExerciseDemo | null;
```

No imports from db/auth/UI. Generated by the script, committed to git.

### 3. Surface `slug` in read types

Several read paths return exercise data without `slug`. Add `slug` to the relevant repo selects / types so UI can resolve a demo:
- exercises list (`ExerciseListItem`) — has nameRu/nameEn/muscles; add `slug`.
- active workout exercise (`ActiveWorkoutExercise`, `lib/repos/workouts.repo.ts`) — add `exerciseSlug`.
- template items, picker items, circuit exercise — add `slug` where the demo is shown.

### 4. Component — `components/app/ExerciseDemo.tsx`

- Props: `slug`, `variant: "hero" | "thumb" | "background"`, `alt` (exercise nameRu).
- Resolves via `getExerciseDemo(slug)`. Local assets (`/exercises-demos/...`) → no `next.config` remote domain needed; cached by the service worker for offline.
- `hero` → animated GIF, large, rounded. `thumb` → small (list/picker/card). `background` → GIF absolutely positioned behind content, with a dark scrim overlay for timer legibility (R-41 contrast).
- `loading="lazy"`; render nothing (or a muscle-icon placeholder) when no demo exists (R-37 empty state — never a broken image).
- Consult `node_modules/next/dist/docs/` for Next 16 image handling before choosing `next/image` vs plain `<img>` for animated GIFs (GIF animation + next/image optimization caveats).

### 5. Surfaces wiring

| Surface | File | Treatment |
|---|---|---|
| List | `app/(app)/exercises/exercises-explorer.tsx` | `thumb` (animated mini-GIF) left of name, lazy, only visible rows. |
| Detail | `app/(app)/exercises/[id]/page.tsx` | `hero` GIF under the title. |
| Active strength card | `app/(app)/workouts/[id]/active-workout.tsx` (`ExerciseCard`) | `thumb` in the card; rest timer uses `background`. |
| Rest timer | rest-timer component (between sets) | `background` GIF of the current exercise behind the countdown + scrim. |
| Circuit timer | `app/(app)/circuits/[id]/active-circuit.tsx` | `background` GIF of `currentExercise` behind the work/rest countdown + scrim. |
| Picker / builder / template rows | `components/app/ExercisePicker.tsx`, `template-builder.tsx`, `templates/[id]/page.tsx` | `thumb` (poster acceptable). |

### 6. Performance

- List shows animated mini-GIFs but **lazy-loaded + only the in-viewport rows decode** (`loading="lazy"`, small render size). If low-end perf suffers, fall back to poster-in-list + animate-on-tap (poster assets already generated, cheap switch).
- GIFs are small (320×320, tens of KB–hundreds). Background variant scaled with `object-fit: cover`.
- Posters (`.webp`) are tiny — used wherever animation isn't needed (picker, builder).

### 7. Offline (PWA / Serwist)

- Precache or runtime-cache `public/exercises-demos/*` so demos work offline (the app is offline-first). Add the glob to the Serwist config.

## States (R-37)

- **No demo** (custom exercise, or unmatched system exercise) → placeholder (muscle icon / initials), never a broken `<img>`.
- **Loading** → poster shown first where available; GIF swaps in.

## Testing

- **Domain:** `getExerciseDemo` (hit/miss, null-safe).
- **Script:** dry-run reports match coverage (X/86) + lists unmatched.
- **Visual (Playwright):** list with thumbs, detail hero, rest timer + circuit timer with background GIF + readable timer text (contrast), placeholder for no-demo exercise.
- **Offline:** cached GIF renders with network off.

## License risk (tracked)

ExerciseDB GIF redistribution rights are unconfirmed. Before selling the product: confirm rights, or swap to a clean-license source (e.g. `yuhonas/free-exercise-db`, public domain) — the manifest + component indirection makes the source swappable without touching surfaces.

## Sequencing

1. **Spike:** build `fetch-exercise-demos.mjs`, run it, report coverage (X/86) + sample a few GIFs for correctness. Curate the override map until coverage is good. (De-risks the whole feature before UI work.)
2. `ExerciseDemo` component + manifest finalized.
3. Surface `slug` in read types.
4. Wire surfaces (detail → list → active/rest/circuit timers → picker/builder).
5. Serwist precache + offline test.
6. Visual tests, fallback states.

## Out of scope (v1)

- Demos for custom user exercises (future: search ExerciseDB on custom-exercise create).
- Video (`videoUrl`) — GIF only.
- Migrating the source to a clean license (tracked separately; trivial swap via manifest).
